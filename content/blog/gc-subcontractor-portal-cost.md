<p>Giving subcontractors direct access to RFIs, submittals, drawings, and pay applications cuts down the email and phone-tag that otherwise eats project engineer time. How that access is priced varies by platform: some construction software gives unlimited external collaborator access with no per-user fee, others cap the number of free external ("light" or "guest") seats and start billing once a GC's sub network grows past it.</p>

<h2>Where the external-user cost actually kicks in</h2>
<ul>
  <li><strong>Capped free external-user tiers.</strong> A common pattern is a fixed number of free external seats included in a plan tier — a GC running many small subs across multiple active projects can hit that cap well before headcount growth would normally trigger a plan review.</li>
  <li><strong>"Do subs count against your user total?"</strong> — the question that matters most before signing. Some platforms count subcontractor and vendor logins toward the same user total as internal staff; others exclude them entirely. The answer changes the real cost of scaling your sub network.</li>
  <li><strong>Per-project vs. per-account access.</strong> A sub working three concurrent projects for the same GC may need access re-provisioned per project on some platforms, adding administrative overhead even where the license itself is free.</li>
  <li><strong>Document and drawing storage limits.</strong> Beyond user counts, some plans gate the volume of drawings, submittals, and photos that can be shared with external users, which can force a tier upgrade independent of subcontractor headcount.</li>
</ul>

<h2>Why this is a genuinely different problem than internal seat cost</h2>
<p>Internal PM seat cost is a headcount-control problem — the goal is usually fewer, right-sized seats. Subcontractor access is the opposite: a GC wants more subs engaging with RFIs and submittals directly, not fewer, because that's what reduces email volume and speeds up the paper trail. A pricing model that caps or bills per external user works against the exact behavior a GC is trying to encourage.</p>

<h2>Frequently asked questions</h2>

<h3>Does a custom subcontractor portal replace our project management software?</h3>
<p>No — it typically sits alongside it, syncing RFIs, submittals, and schedule data via API so subs get a purpose-built view without needing full PM software access themselves.</p>

<h3>How do we find out if subs count against our user total?</h3>
<p>Ask your vendor directly and get it in writing before renewal — this is exactly the kind of detail that's easy to overlook in a sales conversation and expensive to discover later.</p>

<h3>Is this worth it for a GC with only a handful of regular subs?</h3>
<p>It matters most when sub count is growing, turns over frequently across projects, or is already near a free-tier cap — for a very small, stable sub list, the native free tier may already be enough.</p>
